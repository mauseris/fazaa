# فزعة (Fazaa) — وكيل ريادة الذكي | Full Stack، RAG حقيقي، Tool Calling حقيقي

وكيل ذكاء اصطناعي **حقيقي** (وليس واجهة أزرار فوق LLM) يرافق رائد الأعمال العُماني من
الفكرة إلى السجل التجاري. النموذج نفسه يقرر متى يبحث في قاعدة معرفة، ومتى يحسب تكلفة،
عبر استدعاء أدوات فعلي (tool calling) — مطابقاً لما ورد في مخطط المعمارية الأصلي.

```
fazaa-full/
├── server/
│   ├── server.js     ← نقطة الدخول + حلقة الوكيل (agent loop) بمسارين: البوابة/Anthropic
│   ├── rag.js         ← RAG حقيقي: تقسيم مقاطع + embeddings عبر البوابة أو TF-IDF محلي
│   ├── tools.js       ← تعريف وتنفيذ الأدوات: search_knowledge, calculate_cost, identify_stage
│   ├── db.js          ← SQLite حقيقي (better-sqlite3) مع رجوع تلقائي لـ JSON
│   ├── package.json
│   └── .env.example
└── public/
    └── index.html    ← الواجهة الأمامية (عربي/إنجليزي)، تعرض الأدوات التي استخدمها الوكيل فعلياً
```

## ما الذي يجعل هذا "وكيلاً" حقيقياً لا مجرد واجهة؟

معظم مشاريع الهاكاثون تبني تدفقاً ثابتاً بالواجهة (إن كانت المرحلة كذا، اسأل كذا) ثم تنادي
LLM لصياغة الجمل فقط. هذا المشروع مختلف: **النموذج نفسه يقرر** — عبر `tool_calls` حقيقية من
واجهة الـ API — متى يحتاج بيانات من قاعدة المعرفة أو حساب تكلفة، وينفّذ ذلك بنفسه ضمن حلقة
(agent loop) قد تدور عدة جولات قبل الرد النهائي. جرّبنا هذا فعلياً: سؤال "كم تكلفة مطعم في
مسقط؟" يجعل النموذج يستدعي `calculate_cost` أولاً، ثم يقرر بنفسه استدعاء `search_knowledge`
لجلب معلومة رسمية، ثم يصوغ الجواب النهائي — كل هذا بدون أي "if" بالواجهة يفرض عليه الترتيب.

### 🔎 RAG حقيقي (`server/rag.js`)
- قاعدة معرفة من 28 مقطعاً (14 حقيقة × عربي/إنجليزي)، كل مقطع موثّق بمصدره الرسمي.
- **المسار الأساسي:** تمثيلات متجهية حقيقية (embeddings) عبر endpoint البوابة المركزية،
  وبحث بالتشابه الدلالي (cosine similarity).
- **مسار الرجوع التلقائي:** إن كانت بوابتكم لا تدعم `/embeddings`، يبني الوكيل فهرس **TF-IDF**
  محلياً بالكامل عند الإقلاع — تقنية استرجاع معلومات حقيقية، صفر اعتماد على خدمة خارجية،
  فلا ينهار الوكيل أبداً بسبب نقص ميزة بالبوابة. تحقق من الوضع الحالي عبر `/api/rag-status`.

### 🛠️ Tool Calling حقيقي (`server/tools.js` + حلقة الوكيل في `server.js`)
ثلاث أدوات ينفّذها السيرفر فعلياً عند طلب النموذج لها:
- `search_knowledge(query)` → يرجع أقرب 3 مقاطع من RAG مع الرابط الرسمي ودرجة التشابه.
- `calculate_cost(sector, city, teamSize, budgetLevel)` → حساب تكلفة تأسيس حتمي (JS نقي).
- `identify_stage(message)` → تصنيف مرحلة المستخدم: idea / registration / funding / growth.

مدعومة بصيغتين: **OpenAI tool_calls** (عبر البوابة المركزية) و **Anthropic tool_use**
(مسار التطوير المحلي المباشر) — حلقة الوكيل تتعامل مع الصيغتين وتُعيد الأدوات التي استُخدمت
فعلياً ضمن رد `/api/chat`، والواجهة تعرضها كشارة "🔧 استخدم الوكيل: ..." تحت رد كل رسالة.

### 💾 SQLite حقيقي (`server/db.js`)
تخزين جلسات فعلي بـ `better-sqlite3` (ملف `server/fazaa.db`)، وليس ملف JSON بسيط. إن تعذّر
تحميل الحزمة الأصلية على جهاز معيّن (نادر، لكن ممكن)، يرجع النظام تلقائياً لتخزين JSON بدون
أي كسر بالتشغيل — موثوقية العرض أمام اللجنة أهم من الالتزام الحرفي بأداة واحدة.

## ⚠️ الحوكمة الرسمية — البوابة المركزية

بحسب الحقيبة التعليمية (قسم 1.3): لا يُسلَّم أي مشارك مفتاحاً مباشراً؛ الاتصال عبر بوابة
واحدة بمفتاح افتراضي (Virtual Key) وسقف إنفاق. السيرفر يدعم هذا افتراضياً عبر
`GATEWAY_BASE_URL` + `GATEWAY_API_KEY` بتنسيق OpenAI. يوجد أيضاً مساران مباشران بديلان
**للتطوير المحلي/التعليمي فقط** — لا يُسلَّم أي منهما للتحكيم — والسيرفر يطبع تحذيراً واضحاً
طوال استخدام أي منهما. ترتيب الأولوية عند ضبط أكثر من مسار في آن واحد: البوابة المركزية
أولاً، ثم Anthropic، ثم Hugging Face أخيراً.

### مسار Hugging Face Inference Providers (تعليمي)

مسار ثالث اختياري عبر endpoint موحّد متوافق مع صيغة OpenAI
(`https://router.huggingface.co/v1/chat/completions`) يوجّه الطلب تلقائياً لأحد مزوّدي
الاستضافة الفعليين للنموذج (Novita أو Nscale لنموذج Llama الافتراضي أدناه).

```bash
# في server/.env
HF_API_TOKEN=hf_xxxxxxxxxxxxxxxxxxxxxxxx
HF_MODEL=meta-llama/Llama-3.1-8B-Instruct   # الافتراضي — القيمة الصحيحة المؤكدة للنسخة المحادثاتية (Instruct)، وليست القاعدية (base)
```

- **التوكن:** من [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) —
  أنشئ توكن `fine-grained` بصلاحية "Make calls to Inference Providers".
- **⚠️ نماذج مقيّدة (gated):** عائلة Llama تتطلب طلب وصول والموافقة عليه أولاً من صفحة
  النموذج على huggingface.co (بنفس الحساب صاحب التوكن)، وإلا ترجع الاستدعاءات خطأ `403`.
- **Tool calling غير مضمون لكل نموذج:** لا يوجد توثيق رسمي يؤكد دعم `Llama-3.1-8B-Instruct`
  تحديداً لاستدعاء الأدوات عبر هذا الـ endpoint. السيرفر يكتشف ذلك فعلياً عند أول استدعاء
  (رفض صريح من الـ endpoint، أو نص خام يحاكي شكل استدعاء أداة بدل `tool_calls` منظّم) ويرجع
  تلقائياً لوضع محادثة عادي بدون أدوات لبقية التشغيل بدل إخراج استدعاءات مهلوسة — مع تنبيه
  واضح في الطرفية. تحقق من الحالة الفعلية عبر `hfToolCallingSupported` في `/api/rag-status`.

**⚠️ نتائج اختبار فعلي حقيقي على نموذجين (توكن حقيقي، وليس افتراضاً نظرياً):**

**١) `meta-llama/Llama-3.1-8B-Instruct`** — الاتصال والمصادقة والتوجيه عبر
`router.huggingface.co` يعمل صحيحاً 100%، و`tool_calls` تصل فعلاً بصيغة منظّمة سليمة
(`hfToolCallingSupported: true`) — أي أن التكامل نفسه سليم تقنياً. لكن جودة النموذج نفسه
لهذه المهمة (وكيل متعدد الخطوات بالعربية) كانت ضعيفة عملياً: صنّف قطاع "مطعم صغير" خطأً
كـ"tech"، فقد سياق السؤال بين الجولات، أنتج عربية مشوّهة غير مفهومة في استدعاء لاحق، ولم
يتقارب لرد نهائي أبداً — استنفد الجولات الأربع (`MAX_TOOL_ROUNDS`) دون توقف.

**٢) `Qwen/Qwen2.5-72B-Instruct`** (نموذج أكبر، غير مقيّد/gated، لتفادي مشاكل النموذج
الأول) — المصادقة نظيفة تماماً هذه المرة، وجودة الاستدلال بالإنجليزية ممتازة وأوضح بكثير
من النموذج الأصغر. لكن ظهرت مشكلة مختلفة وأخطر: أي سؤال عربي جوهري (مثلاً "كم تكلفة فتح
مطعم في صحار؟") ينتج رداً تالفاً بالكامل — مئات الأحرف الحرفية `?` متكررة بدل نص عربي حقيقي،
بينما التحيات البسيطة ("مرحبا") والردود الإنجليزية تخرج سليمة تماماً عبر نفس الكود بالضبط.
تحقّقنا أن هذا ليس مجرد مشكلة عرض بالطرفية عبر فحص البايتات الخام (`hex dump`) للرد —
البايتات الفعلية هي `0x3F` (علامة استفهام حرفية) متكررة، وليست بايتات UTF-8 عربية صحيحة
يُساء عرضها. تكرر هذا العطل على سؤالين عربيين مختلفين لهذا النموذج تحديداً عبر هذا الـ endpoint.

**الخلاصة:** التكامل التقني نفسه (المصادقة، التوجيه، استدعاء الأدوات، الرجوع التلقائي عند
الفشل) سليم ومُتحقَّق منه فعلياً في الحالتين. لكن **مسار Hugging Face للتطوير غير موثوق حالياً
لهذا التطبيق العربي أولاً بغض النظر عن حجم النموذج** — نموذج صغير (8B) يفشل باستدلال ضعيف
وعدم تقارب، ونموذج أكبر بكثير (72B) يفشل بتلف كامل للمخرجات العربية الجوهرية. **البوابة
المركزية الرسمية تبقى المسار الصحيح للعرض/التسليم**، وهذا بالضبط سبب وجودها كخيار إلزامي
بدل الاعتماد على مزوّدين مباشرين متفاوتي الموثوقية.

## التشغيل (٣ خطوات)

```bash
cd server
npm install
cp .env.example .env      # عبّي بيانات البوابة، واختيارياً EMBED_MODEL_NAME
npm start
```
افتح: **http://localhost:3000**

تحقق من حالة RAG بعد الإقلاع: `curl http://localhost:3000/api/rag-status`

## ما تم اختباره فعلياً (وليس افتراضاً نظرياً)

شغّلت بوابة وهمية محلياً وتحققت يدوياً من:
- ✅ RAG يبني فهرس embeddings حقيقياً عند توفر endpoint، ويرجع لـ TF-IDF محلياً عند غيابه
- ✅ حلقة الوكيل تنفّذ جولات متعددة من استدعاء الأدوات (تم رصد 3 جولات فعلية: حساب تكلفة
  ← بحث معرفي ← رد نهائي) قبل إرجاع النص
- ✅ نتائج RAG مرتبة صح بالتشابه (تجربة "كم رسوم غرفة تجارة عمان" أعادت مقطع OCCI أولاً)
- ✅ SQLite يحفظ/يقرأ/يحذف الجلسات بشكل صحيح
- ✅ التشغيل بدون أي إعداد (`.env` فارغ) لا يُسقط السيرفر — رسالة خطأ واضحة فقط
- ✅ مسار Hugging Face: اختُبر فعلياً بتوكن حقيقي على نموذجين مختلفين —
  `meta-llama/Llama-3.1-8B-Instruct` (استدلال ضعيف، عدم تقارب لرد نهائي) و
  `Qwen/Qwen2.5-72B-Instruct` (استدلال أفضل بكثير، لكن تلف كامل للمخرجات العربية
  الجوهرية، مؤكَّد عبر hex dump للبايتات الخام لا مجرد مشكلة عرض). التكامل التقني نفسه
  سليم في الحالتين — غير موصى به كمسار عرض/تسليم لهذا التطبيق العربي أولاً (تفاصيل أعلاه)

## ملاحظة عن دقة البيانات

أسماء الجهات الحكومية وروابطها الرسمية حقيقية ومُتحقَّق منها عبر بحث ويب مباشر. أرقام
الرسوم والتكاليف تقديرية توضيحية (لا توجد تسعيرة موحدة معلنة لكل نشاط) — مذكور صراحة
داخل التقرير المُصدَّر. المهمة التمهيدية للحقيبة (0.7) تطلب بيانات اقتصادية حقيقية من
محافظتكم — أضيفوها كمقاطع جديدة في `server/rag.js` لتعزيز نموذج القيمة أمام اللجنة.

## تفعيل نموذج حي للوكيل (Gateway أو Anthropic)

إذا أردت تشغيل الوكيل عبر نموذج حقيقي بدلاً من الرد المحلي الاختباري، اتبع الخطوات البسيطة التالية.

- **انسخ ملف الإعدادات:**

  ```bash
  cd server
  cp .env.example .env
  ```

- **اضبط المفاتيح في `server/.env`:**
  - الموصى به (حوكمة): اضبط `GATEWAY_BASE_URL` و `GATEWAY_API_KEY`.
  - للاختبار المحلي فقط: اضبط `ANTHROPIC_API_KEY` (هذا الخيار مخصص للتطوير فقط).

- **أعد تشغيل السيرفر:**

  ```bash
  npm start
  ```

- **تحقق:**
  - حالة RAG: `curl http://localhost:3000/api/rag-status`
  - اختبار المحادثة: استخدم `server/post.js` أو نفّذ `POST /api/chat` من أي عميل HTTP.

- **ملاحظة حوكمة:** لا ترفع مفاتيح API للمستودع؛ احفظها محلياً فقط في `server/.env`.

هذه الإرشادات تُمكّن المسار الكامل لوكيل Tool-Calling باستخدام نموذج خارجي بدلاً من الرد المحلي.
